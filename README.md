# Лабораторная работа №9

Работа с облачным хранилищем и управление конфигурациями проекта.

## Цель

Загрузить файл в S3-совместимое хранилище, скачать его обратно и сравнить
содержимое. Вынести параметры подключения в переменные окружения и исключить
ключи доступа из Git.

## Учебная среда

Используется локальный S3-эмулятор Moto, разрешённый заданием.
Он работает на компьютере по адресу `http://127.0.0.1:5000`.
Внешний облачный аккаунт не нужен. Данные Moto исчезают после остановки сервера.
Тестовый файл содержит названия моделей облачных сервисов: IaaS, PaaS и SaaS.

## Настройка и запуск в Windows

Требуется Python 3.11 или новее. Скачайте репозиторий через **Code → Download ZIP**,
распакуйте архив и откройте терминал в папке с README.md.

### 1 Установка зависимостей

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 2 Настройка облачного хранилища

Создайте локальный `.env` из шаблона:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` в редакторе и заполните его следующими учебными значениями:

```dotenv
STORAGE_ENDPOINT=http://127.0.0.1:5000
STORAGE_BUCKET=student-bucket
STORAGE_ACCESS_KEY=testing
STORAGE_SECRET_KEY=testing
STORAGE_REGION=us-east-1
```

`testing` — фиктивное значение только для Moto, не настоящий секрет.
Переменные задают адрес API, имя bucket, ключ доступа, секретный ключ и регион.
В `.env.example` значения пустые; реальные параметры хранятся только в `.env`
или в переменных окружения. Сам `.env` публиковать нельзя.

### 3 Запуск хранилища

В первом терминале выполните и оставьте его открытым:

```powershell
.\.venv\Scripts\python.exe -m moto.server -H 127.0.0.1 -p 5000
```

### 4 Загрузка и получение файла

Во втором терминале, в той же папке проекта, выполните:

```powershell
.\.venv\Scripts\python.exe app/storage_demo.py
```

Программа создаёт отсутствующий bucket в локальном Moto, загружает `uploads/test.txt`
под ключом `lab9/test.txt`, скачивает его в `uploads/downloaded_test.txt`
и сравнивает байты обоих файлов. При повторном запуске тестовый объект перезаписывается.
После работы остановите сервер сочетанием Ctrl+C в первом терминале.

Для Linux команды аналогичны: `python3 -m venv .venv`, затем используйте
`.venv/bin/python` вместо `.\.venv\Scripts\python.exe` и `cp .env.example .env`.

## Проверка безопасности перед коммитом

В локальном Git-репозитории выполните:

```bash
git status --short
git check-ignore -v .env
git ls-files .env
```

`.env` должен быть исключён, а последняя команда не должна ничего вывести.
Выполненная проверка перед добавлением файлов:

```text
?? .env.example
?? .gitignore
?? README.md
?? app/storage_demo.py
?? requirements.txt
?? uploads/test.txt
```

`.env`, `.venv`, кэш Python и скачанный файл исключены через `.gitignore`.
Для коммита добавляются только безопасные файлы:

```bash
git add .env.example .gitignore README.md requirements.txt app/storage_demo.py uploads/test.txt
git commit -m "Complete lab 9"
git push origin main
```

Не публикуйте настоящие пароли, токены и ключи, в том числе на скриншотах.
`.gitignore` не удаляет уже отслеживаемые файлы или секреты из истории Git.

## Ответы на контрольные вопросы

1. Объектное хранилище обращается к данным через API по bucket и ключу;
   обычная файловая система организует файлы в каталоги.
2. Bucket — контейнер. Объект — содержимое файла, его ключ и метаданные.
3. Вынос параметров позволяет менять среду без изменения программы и не хранить секреты в коде.
4. `.env` содержит рабочие значения; `.env.example` — шаблон без секретов.
   `.env` исключают из Git, чтобы случайно не опубликовать данные доступа.
5. Утёкший ключ может дать постороннему доступ к данным и платным ресурсам.
   Такой ключ нужно отозвать или заменить, затем убрать из истории репозитория.
